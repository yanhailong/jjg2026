## 行为

复用 `NotifyRedDot` 的 `TASK/7` 数量红点，`7` 对应服务器 `TaskConstant.TaskType.ACHIEVEMENT`。
只统计当前已经完成、尚未领取奖励的任务节点，每个节点计 1；主线、协作、已领取、尚未完成的任务不计入。
沿用任务完成和领取后的推送，以及登录、主动查询的初始化路径。

- 主界面 `UISimulation/btn_rwtxz`：显示成就奖励总数。
- 成就界面 `UITaskSystemPanel/rect_medal_info`：每张卡按 `badgeId` 显示数量。
- 建筑信息 `UIBuildingInfo/btn_show_medal_detail`：优先读取实际展示的游戏成就；成就信息到达前按建筑 ID 读取明细。

`extra` 为完整快照，例如：

```json
{"badgeCounts":{"100":2,"200":1},"buildingCounts":{"1001":2,"1002":1}}
```

主界面直接使用 `count=3`，两个明细表不再次汇总到红点树。缺失的键和归零表示没有可领奖励。
打开界面不清除奖励红点，领取后按服务器新快照刷新；总数相同但归属变化时也刷新。
三处均复用 `CommonRedPoint.prefab`，数量为零隐藏，并显示实际数字。
同步修正两处控制器中的旧成就任务类型判断 `3` 为当前的 `7`。
